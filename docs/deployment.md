# Agent 部署引导

当用户说“帮我部署这个仓库”，按以下流程完成安装和引导。不要让用户先读完技术文档，也不要索要聊天中的 AppSecret。安装与配置授权不自动等于允许往任意群发消息；由用户在最终页面选择目标与启用。

## 1. Agent 完成安装

使用用户给出的仓库地址，下载到独立目录，不覆盖已有配置或其他项目。检查 Python ≥3.11、FFmpeg、ffprobe；缺少时按当前操作系统安装，并说明需要用户处理的系统授权。普通用户安装不依赖 Node、前端构建器或浏览器自动化组件。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/bili-fav-relay --config /绝对路径/config.json setup
```

Windows 对应使用 `.venv\Scripts\python.exe` 和 `.venv\Scripts\bili-fav-relay.exe`。不要把 macOS 命令原样贴给 Windows 用户；后续命令应始终使用这个虚拟环境的绝对可执行文件路径。

`setup` 即使配置文件尚不存在也能运行，不用先手工编辑 JSON。它是持续运行的本地设置服务，保留终端/工具会话；输出 `setup_ready` 后，用完整 URL 打开浏览器。仅在运行程序的电脑上有效，不要把 127.0.0.1 链接当作远程部署访问地址。

推荐对用户说：
> 程序已安装，接下来请在本地设置页完成四步。我会根据配置进度继续引导，密钥不需要发给我。

## 2. 只在需要真人操作时提示

用 `setup-status` 读取状态，不读密钥。`job` 是最近记录，可能来自已退出的设置服务，不把旧的 working 当作当前一定在运行。

`source_access` 表示首次配置也会持久保存的冷却/暂停。第一步预检后，至少等 10 秒才能读取完整基线；可在等待时继续填写机器人和绑定群。遇到失败按实际 `next_poll_at` 等待，不通过重开服务或换链接重试。首次配置中的风控暂停可在页面冷却结束后由用户显式“恢复访问”；此操作不发请求，不解除投递暂停，之后仍须手动提交。已有基线的运行故障继续按 status/resume 流程处理。

| next_step | 用户要做什么 | agent 的提示 |
| --- | --- | --- |
| folder | 粘贴公开收藏夹链接或手机分享文字 | “选一个公开收藏夹，不需要 B 站账号或 Cookie；页面会先确认它是公开的。” |
| credentials | 本地输入并验证凭证 | “已有机器人直接填；没有的话，先到 QQ 开放平台创建。” |
| bind | 在目标群发送本次口令 | “等页面显示口令后，在目标群 @机器人发送它。” |
| baseline | 记录已有收藏 | “这一步只读列表，不下载、不发视频。” |
| activate | 选择模式并明确启用 | “可以先用手动同步；只有点击启用，才允许向绑定群转发。” |
| ready | 验证运行状态与新增转发 | “配置已完成；我再确认后台实际运行情况。” |

[QQ 开放平台](https://q.qq.com/)中，开发者账号的创建/认证、机器人可用范围、群消息事件和将机器人加入群，由用户按后台实际显示完成。AppID 与 AppSecret 来自开发设置。用户还须到目标 QQ 群的机器人设置中开启“主动发言”权限；没有权限时由群主或管理员操作。平台允许该群使用机器人、本项目绑定目标群、群内开启主动发言是独立步骤，不能相互替代。不要承诺所有新机器人都已具备主动富媒体权限。

凭证填写在本地页面，由程序验证并存入系统安全凭据库。不要通过聊天、截图、命令参数或日志收集密钥；也不要去读取其他软件的机器人配置。凭据库不可用时按错误提示处理，不安装明文 keyring 后端充数。

绑定码由真实 Gateway READY 之后产生，有效期约 5 分钟；页面显示的是本次实际口令。不要自己编造一个六位数，也不要让用户发送开发平台的 AppSecret。群备注是用户命名，不把它当作 QQ 平台自动查询到的群名。

## 3. 验收部署，不只看“启动成功”

1. `setup-status` 确认收藏夹、凭证记录、群绑定与基线齐全；其中“已保存”不代替实际接口验证。
2. `status` 查看 `runtime.active`、`runtime.last_tick_at`、模式、暂停标记及上次调度结果。后台进程在跑但本轮失败时，必须说明具体问题。
3. 用户明确要测试转发时，让用户新收藏一条普通短视频，再调用 `sync` 或由用户点击“立即同步”。保留最低 10 秒源冷却，不用删状态或重启绕过。
4. 区分“请求已提交”“QQ 接口返回回执”和“用户在群里确认收到”，按实际证据汇报。

不要把历史收藏自动发一遍当作测试。没有新增时，诚实说明暂无新增；不偷偷挑一条旧视频发到群里。

## 4. 离开设置页后的运行

`start` 启动独立后台进程，标准输入已断开且日志写入配置对应的 data/worker.log；关闭页面/终端后可继续运行。`stop` 提交协作停止，当前一条结束后退出；用 `status` 等待实际停止。

**当前没有自动安装登录/开机服务。** 电脑重启后让用户再说“启动投石机”（旧说法“启动收藏转发”同样有效），agent 调用 start 即可。如果用户要求开机启动，另行配置与操作系统匹配的用户服务，使用绝对配置路径和虚拟环境 Python，先完成可审阅服务定义，再安装验证。不要把现有 start 宣称成开机自启。

后台进程不依赖 agent 留在线上。当前“立即同步”包含已排队但未发送的新增；“从用户这句话的时间开始”的临时会话尚未实现，不能把两种语义混用。

## 5. 可恢复的常见卡点

| 状态 | 处理 |
| --- | --- |
| Python/FFmpeg 缺失 | 补齐后重新打开页面；依赖状态会自动更新 |
| 系统凭据库锁定或不可用 | 用户解锁钥匙串/凭据库并允许访问；无桌面服务器改走 README_AGENT.md 的环境变量配置 |
| 机器人验证失败 | 按页面提示处理：11298 为 IP 白名单（家庭宽带 IP 变化后要更新），其余核对 AppID/AppSecret、平台权限与网络；不连续快速重试 |
| 群发送失败 40034105 | 请用户在目标 QQ 群开启机器人“主动发言”；保留任务与暂停，不反复重试。修复后按下文恢复 |
| 绑定一直等待 | 核对目标群内机器人、@操作、当前口令与事件权限；过期后重新生成 |
| 收藏夹私密/预算不足/风控 | 看 status 的错误原因；公开性与分页预算可修正；暂停需用户明确解决原因后 resume |
| 设置页打开时已有 worker | 先用 stop 并确认退出，再修改收藏夹/凭证；日常模式与间隔可直接调整 |
| 重开页面显示已停止 | 点击后台启动，或 agent 调用 start；已有配置不用重新填写 |
| 新电脑只恢复了配置文件 | 系统密钥不会随配置备份迁移，需重新填写；保留去重数据库与绑定 |

仓库当前仍是开发版；已验证和未验证的范围见 [verification.md](verification.md)，尤其新用户真实机器人绑定和跨平台安装。

## 自定义同步间隔

启用页和完成页都支持数值加秒/分钟单位，最短 10 秒、最长 24 小时；默认仍为 15 分钟。agent 可使用 `schedule --seconds 10` 或 `schedule --minutes 10`，不能同时填写。只切换模式会保留原间隔。10 秒是请求轮次的下限，分页与投递仍串行进行，不承诺 10 秒内收到视频；不为验收该设置去高频请求真实平台。失败退避和风控暂停优先于用户间隔。

## 主动发言被拒后的恢复

`status` 的 `control.delivery_problem` 显示脱敏的 `code`、`http_status` 与 `message`。已知的 `40034105` 权限拒绝记为 `failed`；它与超时等 `uncertain` 分开。先请用户在目标群开启机器人的“主动发言”，确认没有其他暂停原因；在用户允许重试本条视频后，停止 worker 并等 `status` 确认已停止，再执行 `retry <BV号>`、`resume`、`sync`。需要长期运行时再 `start`。不自动更换机器人、群或凭据，不清理去重记录。旧版留下的 `uncertain` 仍由用户核对后 `resolve`，不推断它一定没发送。

首次打开设置地址缺少会话时，页面显示恢复提示。将启动时的完整链接粘贴到同一标签页即可自动重新载入；无效 token 仍会被拒绝。完整链接只给当前设备上的用户，不能放进 issue、日志或公开截图。
