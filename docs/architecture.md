# 架构草案（2026-10-22）

## Claude 版本基线上的恢复修正

保留像素直播间、角色对话、四步表单和平台错误说明。新增 `core/source_access.py` 统一预检与扫描的请求预约、冷却和失败退避；`setup/folder_setup.py` 编排候选收藏夹预检及首次配置的显式恢复。Store 负责校验旧基线归属和事务提交；预检失败只记录请求状态，不改已保存的收藏夹与绑定。UI 在第一步/基线处显示等待或暂停，并提供首次配置恢复入口。数据流：页面 → SetupService → 请求预算 → 短链/预检 → Store + 私有配置写入；状态仍由 SQLite 持有。未建立基线也保留请求记录，重开页面不重置预算。
目标：公开 B 站收藏夹新增普通投稿 → 匿名低画质 MP4 → 用户自己绑定的 QQ 官方机器人 → 群视频。

第一版暂按单用户自部署设计，CLI；持续监控由独立 worker 进程运行，agent 退出不应销毁监控。用户已确认 agent 只协助安装，日常运行不依赖 agent。

| 目录 | 职责 |
| --- | --- |
| sources/ | 收藏夹全分页快照与匿名视频下载 |
| targets/ | QQ OAuth、分片上传、群消息发送 |
| core/ | 首次基线、永久已见记录、持久队列与失败状态 |
| config.py | 本地配置、凭据环境变量、限额 |
| store.py | SQLite 单一状态持有者、事务 |
| cli.py | 命令行安装、配置与运行入口 |
| vendor/ | 独立打包的已有匿名下载实现，无全局 skill 路径依赖 |
| tests/ | 增量、重启、重复与发送失败测试 |

数据流：CLI/worker → 服务层 → source 快照 → SQLite 原子登记新内容和队列 → 下载验证 → target 上传 → 记录发送中 → 发消息 → 记录回执。

默认基线不发送历史。已见 BV 永久保留，移出再加不重发。没有消息回执的发送不自动重试。群 OpenID 与机器人配置共同决定目标，禁止把 QQ 群号当 OpenID。

规模假设：单进程 worker、一个用户、多条少量订阅；默认 900 秒扫描，20 条/页，默认最多 5 页（可设置 1–50）；不承诺轮询间加入又删除的视频会被发现。

正式发布前必须验证真实 QQ 机器人主动消息能力、群绑定来源和视频可播放效果。

## 日常控制入口（实现前设计）

| 模块 | 职责 |
| --- | --- |
| core/control.py | 页面/CLI 共用的间隔、自动/手动模式、一次性同步命令与状态 |
| core/scheduler.py | 自动周期与显式同步任务调度；限频、暂停和发送额度继续生效 |
| worker.py | 装配平台适配器与进程锁；运行循环，不承担交互语义 |
| store.py | SQLite meta 保存控制设置、一次性请求和结果；事务合并重复请求 |
| cli.py | 将命令映射到控制服务，输出可供 agent 解释的 JSON |
| docs/agent-usage.md | 自然语言到确定命令的映射、授权边界、结果解释 |

数据流：页面（后续）或 agent → CLI/Control → SQLite → 唯一 worker → Pipeline → source/target。
控制命令不等待 worker 生命周期锁，worker 在任务边界读取新设置；当前正在处理的一条允许结束。
手动模式只停止自动轮询/投递，显式同步任务可运行；一次同步只扫描一次，并处理该次扫描后冻结的待发队列。
重复同步请求合并；冷却不绕过，任务返回等待时间；发送关闭时不自动开启。
初次建立基线不发历史；失败、不确定状态不能经由“立即同步”自动重试。
不新增公网入口、MCP 服务或模型依赖，不接触实际用户凭据与线上状态。

## 首次部署向导（实现前设计）

任务映射：粘贴公开收藏夹 → 收藏夹页；申请/填写机器人凭证 → 机器人页；群内口令 → 目标群页；建立历史基线并选择启动方式 → 启用页。完成后同一页面显示运行状态与同步操作，不添加空导航页。

选型：沿用 Python 标准库本地 HTTP 服务 + 分文件 HTML/CSS/ES modules。该产品是单用户、四步表单，无 SSR/SEO 需求；相比引入 React/Vite，不增加用户安装 Node 的要求；相比桌面 WebView，不增加多平台打包门槛。页面后续增长到多订阅/复杂历史视图时再评估组件框架。

| 模块 | 职责 |
| --- | --- |
| credentials.py | 仅调用系统安全凭据后端，配置保存引用；环境变量继续兼容 |
| local_files.py | 私有文件原子写入，非敏感配置保存 |
| setup/service.py | 收藏夹、凭证验证、绑定、基线与启用业务，复用现有适配器和 Control |
| setup/jobs.py | 单任务异步执行与脱敏进度，慢接口不阻塞页面 |
| setup/server.py | 仅回环地址；随机会话令牌、Host/Origin 校验、请求大小与频率限制 |
| setup/ui/ | 静态外壳、页面步骤、请求与交互、样式分离 |
| runtime.py | 独立后台进程启动、状态握手、协作停止；不自动安装开机服务 |
| docs/deployment.md | agent 部署路径、真人操作点、失败恢复与运行验收 |

数据流：浏览器 → 令牌认证的回环 API → SetupService → 已有配置/Store/平台适配器；密钥 POST 后只进入系统凭据库，状态和响应不回显。agent 通过 setup-status 获取非敏感进度。用户点击启用才允许后台转发。

视觉：克制的工具向导，借鉴系统设置的行距和明确主操作；白色主体、浅灰背景、深青行动色，单层面板与左侧步骤。正文 15px，标题 26px，操作热区 ≥44px；窄屏步骤改横向。无装饰性图表、无大幅渐变。加载、未配置、错误、凭据库不可用、部分完成均提供具体下一步；支持键盘、暗色和减少动效。

后续演练：多订阅增加订阅选择与服务工厂；历史页增加独立 UI 模块及只读 API；开始/结束临时会话接 Control，均不改变密钥或 HTTP 安全层。本次不实现会话时间边界。

## 秒级同步间隔

用户任务仍在向导启用页与完成页：选择手动/自动，输入数值与秒/分钟单位。沿用像素直播间样式。config.py 统一校验 10–86400 秒，Control 保存秒值；CLI/SetupService 将输入交给同一规则，setup-status 同时提供秒值和兼容分钟字段。SourceAccess 保留分页预算、持久失败退避与风控暂停，Scheduler 串行执行，不增加并发请求。默认 900 秒和现有用户配置不自动改变。

## 设置会话恢复与明确投递拒绝

会话恢复仍在 setup/ui/app.js：同标签页带 token 的 hash 变化触发重新加载，沿用服务端会话认证。targets 层保留 QQ 数字码/HTTP 状态并把已知权限拒绝映射为 core/delivery_errors.py 中的通用异常；core/Pipeline 只区分明确拒绝与结果不明，不识别平台错误码。Store 的现有 meta 保存脱敏投递原因，Control/status 投影到 CLI 和页面；不新增数据表、不迁移旧 uncertain、不在权限恢复时自动重发。群内权限指引放在绑定页、启动页和部署文档。
